Built apps/spout-bridge/spout_shim (C++ extern "C" shim over SpoutLibrary):
  - spout_shim.cpp compiled with MSVC + linked against SpoutLibrary.lib -> spout_shim.dll
  - SpoutLibrary.dll copied alongside

Rust adapter: crates/integrations/src/spout.rs (feature `spout`) runtime-loads the shim.

VERIFIED:
  - Sender enumeration (GetSenderCount/GetSender/GetSenderInfo) via `flux spout`.
  - Offscreen WGL context creation succeeds (`flux spout-send` prints "offscreen GL ready: true").

NOT WORKING (documented, not faked):
  - SpoutLibrary CreateSender/SendImage through the offscreen WGL context returns
    failure on this host, so `flux spout-send` sends 0 frames. Spout's GL path expects
    a sender created within the application's real rendering context; a bare offscreen
    context is insufficient. Correct fix is to send from Flux's existing wgpu device via
    a shared DX11 texture (SpoutDX), which is a larger interop task.
  - GetSenderCount can block when no sender exists (bounded by the adapter's 3s timeout).

Status: sender enumeration + GL-context init verified; live SendImage via offscreen GL
does not work and is reported as a limitation. The adapter fails honestly (returns 0)
